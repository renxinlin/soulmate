# 多人说话识别链路（multi_speaker）— 需求文档

> 状态：**需求稿 v1，未落库**。本文只定义「做什么、边界在哪、怎么算验收」。
> 实现细节（类、接口、参数、许可）见 `docs/multi_speaker_pipeline_design.md`。
> 本文**取代** `docs/speaker_pipeline_design.md` 的 §2 流程拓扑与 §5 编排器；那份文档的 §4 接口清单继续作为组件目录。

---

## 0. 需求原始描述（保留原文口径）

1. 重新设计：**先识别出几个人说话**（注意考虑边界情况）。
2. 如果**一个人** → 注册**临时声纹**。
3. 如果**多个人** → 先根据**已知声纹和临时声纹**进行**说话人分离**，同时确认**谁在说话**。
4. 最后进行 **ASR**。

---

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 判据 |
|---|------|------|
| G1 | 一句话开始前先回答「**几个人在说**」，并把 1 人和 ≥2 人**路由到不同链路** | 计数有明确输出结构（含 0 / 1 / MULTI / UNCERTAIN）、有置信度、有证据位图 |
| G2 | 判成 1 人时**绝不调用分离** | 单人路径延迟不包含任何分离耗时 |
| G3 | 未知单人说话人可获得**会话内临时身份**，能用来指代（「他刚才说」） | 临时 id 与正式 id 前缀、状态、生命周期、导出行为全部可区分 |
| G4 | ≥2 人时用**已知声纹 + 临时声纹**做目标提取，并输出**每人说话时间段**（谁在说 / 何时 / 多久） | 每路 `activity` 时间线与 ASR 文本一一对应 |
| G5 | 每条输出文本都带「谁说的 + 可信度」 | `SpeakerText` 里 `identity_kind ∈ {known, provisional, none}` 且 `score` 可解释 |
| G6 | 全程**离线**、可商用许可、板端算力预算内可跑或明确降级 | §6 非功能需求 + 设计文档 §9 许可章节 |
| G7 | 边界情况**逐条有期望行为**，不允许「未定义」 | §4 的 E01–E20 全部映射到设计文档规则与 TC 用例 |

### 1.2 非目标

* **不承诺精确人数**。只承诺 `{0, 1, ≥2}`；人数 >3 时给上界 `n_upper` 供聚类搜索，不给「就是 4 个人」这种输出。
* **不解决鸡尾酒会里的全量盲分离**（不认识的 N 个人全部拆干净）。只做「已知/临时声纹锚定的目标提取」，其余进残差，残差达不到质量门控就整段标 suspect。
* **不做声纹注册的正式入口**。正式注册仍走 `docs/voiceprint_pipeline_design.md` §6.1 的两步式 + 同意；本链路只产生临时身份与「建议注册」事件。
* **不做活体/反欺骗**，不区分「电视里的人」与「在场的人」（见 E11，只能降权与提示）。
* 不做 TTS 内容生成、不做多轮对话策略。

## 2. 术语

| 术语 | 含义 |
|------|------|
| 计数 (counting) | 判定一段语音里有几个说话人，输出 `{0,1,MULTI,UNCERTAIN}` |
| 同时多人 (simultaneous) | 两人在**同一帧区间**都在发声 → 需要分离 |
| 时序多人 (sequential) | 两人在**同一条 utterance 内先后**说话（无帧级重叠）→ 不需要分离，需要**切句** |
| 目标提取 (TSE) | 给定目标声纹，从混合中提取该人；区别于盲分离 BSS |
| 活动线 (activity) | 每个说话人的发声帧序列，即「谁在说 / 何时说 / 说了多久」 |
| 临时声纹 (provisional) | 本链路自动产生的会话内身份，未经人工确认、未经同意、默认不落盘 |
| 锚定 (anchoring) | 用已知 + 临时声纹质心当参照，给每个时间窗打分，形成 `score[window, speaker]` 矩阵 |
| 泄漏 (leakage) | 提取 A 时把 B 的一部分能量带进输出，残差里会形成「假人」 |
| 主判据 | 本文里指「滑窗嵌入 + 簇结构」，其余为佐证证据 |

> **术语纠正（必须写进实现）**：`segment` 的 `suspect_reasons` 里的 `overlap_Nms`（collector.py:543，由负 `holes` 算出）指的是**采集时间轴上两句话交叠**，与本文说的「多人同时说话」毫无关系。计数模块不得复用该字段做判断。

## 3. 主流程

```
bundle (segment 的整句交付载荷)
   │
   ├─ 0. 预门控：静音 / TTS 回声 / 采样率不符 ────────────────► 丢弃（不调任何模型）
   │
   ├─ 1. 【计数】几个说话人？ ──┬─ 0 人 ─────────────────────► 丢弃
   │                            ├─ 1 人 ─┬─ 已知 ─► 记命中、更新活动线 ─► 4
   │                            │        └─ 未知 ─► 【临时声纹】(会话内) ─► 4
   │                            ├─ 时序多人 ─► 回切句请求（交回 segment 裁成多句）─► 各自按 1 人处理
   │                            └─ ≥2 人同时 ─► 2. 【目标提取】+ 【活动线】
   │
   ├─ 2. 分离：以 已知声纹 + 本会话临时声纹 为 target，逐人提取（上限 K 路）
   │        残差 → 泄漏门控 → 若有干净的新人 → 再建一个临时声纹
   │
   ├─ 3. 活动确认：每人一条帧级 activity（软分配 + VAD），据此判断「谁在说」
   │        质量不达标的路 → 丢弃并计入指标，不进 ASR
   │
   └─ 4. ASR：每一路独立送 ASR（复用 segment 的采集链，每路一个实例）
            输出 SpeakerText{text, speaker_id, identity_kind, score, activity, confidence}
```

顺序要求（硬性的，不能反）：**计数 → 路由 → 分离 → 活动 → ASR**。
「先分离再数人头」被明确禁止：分离伪影会让计数与声纹都不准，而且最贵的那一步跑在了不该跑的分支上。

## 4. 边界情况清单（本需求的核心）

每条必须有期望行为；实现里对应设计文档的一条规则和一个测试用例。

| # | 边界情况 | 期望行为 |
|---|----------|----------|
| E01 | 整句 < 最短计数窗（默认 1.5s），根本切不出两个窗 | **不许判 MULTI**。退回「单向量 vs 锚点」判定，`level=UNCERTAIN`、`count_confidence=low`；走单人路径，但**禁止建临时声纹**（样本太短，会污染库） |
| E02 | 两人先后说话，被 segment 拼成一条 utterance（时序多人，无帧级重叠） | 判 `MULTI` 但标 `mode=sequential`：**不分离**，改为向 segment 侧发**切句请求**（按窗间簇切换点裁成 2 条），裁出的每条按单人链路走，且允许建临时声纹 |
| E03 | 两人同时说话（帧级重叠） | `mode=simultaneous`，走目标提取；重叠帧占比进 `overlap_ratio` |
| E04 | 库里已有 A、B，实际只有 A 在说（B 被提到或在场静默） | 不得判成 2 人。判据是**帧级**分数矩阵只有一行持续高，B 的分数只在被提及的语义里出现——声学链路与语义无关，天然不会误判；但要求实现里「同一窗内多个已知人高分」才算证据，避免拿 top-k 的静态排序当计数 |
| E05 | 说话人是儿童 / 远场小声 / 重口音，与所有已知人分数都低且窗间不稳 | 允许降为 `UNCERTAIN` 而不是 `MULTI`（**低质量 ≠ 多人**）。此时不分离、不建临时声纹、只出 ASR，并在结果里带 `count_confidence` |
| E06 | 机器人自己的 TTS 被麦克风收到 | 预门控直接拦（复用 voiceprint C15 的 `Verdict.TTS_ECHO`）。**不允许把自己算成一个说话人**，这是产生「幽灵第二人」最常见来源 |
| E07 | 电视 / 音箱外放人声，且外放里正好是已注册的人 | 声学上无法区分。要求：把「外放」当作已知不确定项，输出照常，但**禁止对同时多人路径的残差建临时声纹**（外放声纹会伪装成陌生人入库），并提供 `环境:` 标签供人工修正 |
| E08 | >3 人同时 | 只输出 `MULTI` + `n_upper=min(K, 4)`；提取按优先级只做前 K 路（默认 3），其余进残差且**只标 unresolved**，不硬拆 |
| E09 | 纯噪声 / 无人说话 | `count=0`，不调任何模型，不产生事件 |
| E10 | bundle 带 `suspect_reasons`（空洞补零、段间 gap、aborted、max_duration 截断） | 计数**允许**跑（数人不依赖完整句），但**禁止建临时声纹**、禁止 absorb。截断句尤其禁止：半句会拉偏质心 |
| E11 | 单通道设备（无麦阵）或两麦间距不足以产生可用相位差 | 空间证据层整体缺席，`evidence` 位图相应置灰；仅靠频谱层 + 嵌入层判定，阈值相应收紧（**更容易判 UNCERTAIN**），并在指标里与多通道分开统计 |
| E12 | 同一个人在句中换位置 / 转身 / 走远 | 不得因分数下移而判多人。要求「窗内一致性」与「跨锚点区分度」**分开算**：同一锚点的分数位移不是多人证据 |
| E13 | 目标提取把 A 的一部分漏进残差，残差聚出一个「假第三人在说」 | 残差聚类前必须过**泄漏门控**：残差窗与某个已提取人的嵌入 cos 高 ⇒ 判泄漏，丢弃该窗，不许新建临时声纹 |
| E14 | 临时身份和库内某人其实是同一个（会话内先当陌生人，后来确证） | 提供 `merge_provisional(tmp_id, speaker_id)`：会话内指代关系改写 + 临时向量丢弃（**不回写正式模板**，因为分离/低质量来源不可信）。自动检测阈值触发提示，人工确认才并 |
| E15 | 会话结束但上下文还引用着临时身份 | 临时表在 `provisional_ttl_s` 后回收；若引用未断，输出里的 `speaker_id` 变成 `tmp_*` 的历史字符串并标 `identity_kind=none`（宁可说「不知道」，不说错名字） |
| E16 | ASR 在分离输出上产生幻觉文本 | 只有 `activity` 覆盖率与质量分达标的路才送 ASR；送之前每路再做一次「像不像语音」门控。ASR 文本必须带 `source_quality`，供下游拒用 |
| E17 | 用户要求「同时多人也直接给我全部文本」 | 允许，但重叠帧的文本必须带 `overlap=true` 且置信度降级；不允许上层把重叠帧的文本当某个人的原话入库 |
| E18 | 计数模块本身崩溃 / 后端缺失（模型没装、onnx 加载失败） | **退化成单人路径 + 不建临时声纹**（等价 E01 的低置信分支），并打 `degraded=counter_unavailable`。绝不允许因为计数不可用而整链路停摆 |
| E19 | 同一句话被重复投喂（重放、多 sink、上层重试） | 计数与临时声纹都按 `dedup_key` 幂等（沿用 voiceprint §3.2）；重复不新增临时向量 |
| E20 | 长时间只有一个人但一直不被注册（陌生常客） | 临时声纹**不跨会话累积**，但 unknown 计数可以：达到 `unknown_prompt_after` 触发「建议注册」事件，注册仍须走正式两步式 + 同意 |

## 5. 功能需求

| # | 需求 |
|---|------|
| F1 | 输出结构化计数：`level ∈ {ZERO, SINGLE, MULTI, UNCERTAIN}`、`mode ∈ {none, sequential, simultaneous}`、`overlap_ratio`、`n_upper`、`confidence`、`evidence`（证据位图：空间/频谱/嵌入/锚定） |
| F2 | 计数必须在**ASR 之前**、在**分离之前**完成，且 1 人路径可早退 |
| F3 | 单人不认识时创建临时声纹：多窗聚合、会话内 id、`identity_kind=provisional`、默认不落盘、不导出、不参与权限判定 |
| F4 | 临时声纹可参与后续计数锚定与目标提取（即「临时声纹」在本文里既是身份也是分离的 side information） |
| F5 | 多人时逐人目标提取，targets = 已知声纹 ∪ 本会话临时声纹，上限 `max_extract_targets`（默认 3），按质量分/活动时长排序 |
| F6 | 每人一条帧级 activity；输出「谁在说、起止毫秒、发声占比」 |
| F7 | 残差处理：泄漏门控 → 可选聚类 → 只允许产生 `provisional`，并标 `via_pipeline=True` |
| F8 | 每路独立 ASR，结果带身份、分数、活动区间、质量与 `overlap` 标记 |
| F9 | 切句请求能力（E02 时序多人）：把簇切换点交给 segment 侧裁成多条 bundle |
| F10 | 全链路可解释：一条 `explain()` 文本能回答「凭什么判这么多人 / 凭什么说是他 / 这一路为什么丢」 |
| F11 | 每个决策点可观测（§6 N6）与可回归（设计文档 §12 TC 用例） |
| F12 | 任何模块缺失都能降级跑通（E18），不允许硬依赖 GPU 或未确认许可的权重 |

## 6. 非功能需求

| # | 要求 |
|---|------|
| N1 | **延迟**：计数不得成为新瓶颈。目标：1 人路径总增量 ≤ 30 ms（板上待实测，见设计文档 §10）；多人路径可异步（先回内容、后补身份），但必须给出「身份补齐」回调时限 |
| N2 | **算力**：无 GPU。目标硬件 RK 级 CPU；所有模型必须能在 CPU 上跑，或明确标注「需 NPU/需实测才能启用」。TSE 是链路里最贵的一步，未实测前默认关闭（`separation_enabled=False`） |
| N3 | **内存**：新增占用上限必须给数（嵌入窗缓存 + 临时表 + 分离缓冲），并写进 `validate()` 的不等式 |
| N4 | **商用许可**：链路上每一个权重（计数 / VAD / 声纹 / 分离 / ASR）都要有代码 + 权重 + 训练数据集三层链条的书面出处；缺任何一层即不得出厂。详见设计文档 §9 |
| N5 | **隐私**：临时声纹的产生必须在隐私政策里可描述；默认不存音频；未同意的生物特征模板不得跨会话留存。E06/E07/E13 三条是「误建身份」的主要风险面 |
| N6 | **可观测**：计数分布、判多人比例、早退命中率、临时表命中/合并/回收数、每路 activity 覆盖率、ASR 文本被质量门控丢弃的比例 |
| N7 | **可测**：全部逻辑可用无模型的 stub 后端跑通（沿用 segment / voiceprint 的既有约束） |
| N8 | **离线**：运行期不出网、不下模型；权重预置 |

## 7. 验收标准

1. **计数**：在自标定集上 `SINGLE vs MULTI` 的二分类准确率 ≥ 目标值（目标值由产品定，本文不代定），且**误判 MULTI 的比例**必须显著低于误判 SINGLE 的比例（理由见 §1.2 与 N1 的代价不对称）；`UNCERTAIN` 允许出现的比例上限也需标定。
2. **时序 vs 同时**（E02/E03）：`mode` 判定与人工标注一致；时序多人**不得触发分离**。
3. **早退**（G2）：1 人路径的耗时分布里**不含**任何分离/残差环节。
4. **临时声纹**：会话内可指代；会话结束后内存表为空；`export()` 与 `find_by_label()` 查不到临时身份；未经同意不会产生正式模板；E14 合并路径可回滚。
5. **多人**：每个真实说话人的 activity 起止误差 ≤ `activity_tol_ms`（标定项）；ASR 文本与说话人对应正确；残差泄漏造成的「假人」在回归集上为 0（E13 门控有效性）。
6. **许可**：出厂清单里每个权重的三层链条都有官方 URL + 抓取日期 + 书面确认（N4）；未闭环的组件必须处于关闭状态。
7. **边界**：§4 的 E01–E20 每一条都有对应测试用例且通过；任何一条「未定义」视为不验收。

## 9. 待确认决策

* **Q1 是否允许临时声纹落盘**。不落盘（推荐，风险最小、重启即失忆）还是落盘但会话级过期（能跨重启指代，但产生「未经同意的生物特征留存」问题）。
* **Q2 板端到底跑不跑得起 TSE**（N2）。跑不起则多人路径退化为「只标 overlap + 只出整句 ASR」，功能面差别很大，需要产品知情。
* **Q3 外放/电视（E07）要不要做产品级规避**（如结合播放状态、屏幕声纹、播放音量的先验）。
* **Q4 `max_extract_targets` 取几**。越大越像「全分离」，但失真与延迟叠加，且残差门控更难。
* **Q5 计数与活动是否需要单独的前端模型**（如专门 trained 的 segmentation 模型），还是只用「嵌入窗 + 锚点矩阵 + 频谱证据」。前者精度更高、许可与算力成本也更高。
* **Q6 时序多人（E02）由谁裁句**：segment 侧重切（本文假设），还是本模块自己裁（会复制一套切句逻辑，两处口径迟早漂）。
